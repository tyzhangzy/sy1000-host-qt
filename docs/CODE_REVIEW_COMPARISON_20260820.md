## 5. 实质差异分析（3 个值得注意的升级点）

### 5.1 H1：从"表面问题"到"数据可信度问题"的跨越

- 昨日 #10 只观察到 `testStandardInfo()` 中文硬编码（i18n 层面），**没有发现试验标准根本没有真正用于判定与落库**。
- 今日通过 QML↔C++ 交叉核查（`setTestStandard` 调用链 → `buildResult()`）发现：
  - 准备页确实调用了 `setTestStandard/setWorkingPressure/setTestingPressure`（接线存在）；
  - 但 `buildResult()` 硬编码 `standardName="Demo"`、`residualDeformationRate=3.0`，`m_standardName/m_residualRate/m_holdTime` 从未被使用；
  - 控制器残变率限值固定 3.0，`setTestStandard` 不更新。
- **结论**：UI 显示与存档/判定不一致，属必改项。昨日审查停留在代码表面，今日通过调用链核查才暴露这一核心缺陷。

### 5.2 H5：合规/监管维度，昨日完全未覆盖

- 昨日聚焦"安全（密码）/硬件（串口）/可靠性"，未审查"试验流程合规性"。
- 今日发现"开始水压试验"按钮不校验 `saveSample()`，`buildResult()` 会把 `inspectionCompleted=false` + 默认"合格"写入存档 → 可能产生未经外观检查的"合格"正式记录。在气瓶检验场景属监管风险。

### 5.3 M10：昨日 #17 只提性能，今日深入线程安全

- 昨日 #17："每 100ms 发 5 个信号 + `m_curvePoints` 无上限"（性能）。
- 今日补充两点：`QQuickPaintedItem` 的 `paint()` 在渲染线程执行，而 `m_cacheValid/m_yMin/m_yMax/m_isPaused` 在 GUI 线程无锁读写（数据竞争）；且 `addSeriesValueAt` 每次置 `m_cacheValid=false`，使"单序列增量绘制"分支成为永不执行的死代码。
